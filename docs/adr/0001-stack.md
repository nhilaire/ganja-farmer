# ADR 0001: Expo (CNG) or bare React Native

Status: accepted
Date: 2026-10-16
Decision: expo

> `Decision:` is `expo` or `bare`. `Status:` becomes `accepted` only after the user agrees.

## Context

Ganja Farmer is a port of an existing **Expo** project (SDK 55, local prebuild, `@shopify/react-native-skia`,
zustand, AsyncStorage, one custom config plugin for fullscreen immersive mode). The PRD (v0.1.0, approved) needs:

- **Rendering:** a full-screen Skia canvas redrawn every frame. The source uses `createPicture` + `<Picture>`
  driven by a `requestAnimationFrame` loop. There are up to ~4 helicopters, 15 paratroopers, dozens of bullets,
  explosions and particles: well beyond what Views + Reanimated handle well, so the choice is **Skia**.
- **Orientation:** landscape lock (`expo-screen-orientation` or `orientation: "landscape"` in app config).
- **Display:** fullscreen immersive (system bars hidden, swipe to show), done today by a config plugin that edits
  `MainActivity` and the theme.
- **Splash:** the native splash (`expo-splash-screen`) followed by a custom 2 s splash image drawn in JS.
- **Sound:** short sound effects with a mute toggle (`expo-audio` + `expo-asset`).
- **Vibration:** patterns such as `[0, 50, 30, 50, 30, 100]`. React Native's `Vibration` API supports patterns;
  it needs the `VIBRATE` permission, added through app config.
- **Storage:** AsyncStorage for high scores, settings and consent.
- **Telemetry:** opt-in Firebase Analytics + Crashlytics (React Native Firebase, config plugins).
- **Pause:** `AppState` from React Native core.
- **Build:** local Gradle on Windows, signed arm64 APK, sideloaded; no EAS, no cloud.

## Criteria

| Criterion | Weight | Expo (CNG + prebuild) | Bare React Native | Notes |
|---|---|---|---|---|
| All required libraries work with Expo prebuild / config plugins | high | yes | yes | Skia, expo-audio, expo-screen-orientation, AsyncStorage, RN Firebase: all autolinked, New Architecture ready, installable with `npx expo install` |
| Need to hand-edit native Android code continuously | high | no | no | the only native tweak (immersive mode) is a one-time edit, already written as a config plugin in the source |
| Custom native module (Kotlin/C++) needed | medium | no | no | |
| Upgrade effort over time | medium | low (bump SDK, `expo install --fix`) | high (Upgrade Helper merges) | the factory's other apps are on Expo SDK 57 |
| Build simplicity on this machine (local Gradle) | medium | `build-apk.mjs` prebuild + gradlew, proven on 2 apps | gradlew, proven by no app here | |
| Firebase setup effort | low | config plugins | manual Gradle setup | |
| Continuity with the source project | medium | same stack (Expo + Skia), code and plugin reused | needs the native project rebuilt by hand | |

## Decision

**Expo (CNG, local prebuild), SDK 57 as pinned by the factory**, with **Skia** rendering
(`@shopify/react-native-skia` via `npx expo install`).

1. Every library the PRD needs works with Expo prebuild, and none forces bare. The source game already runs on
   Expo with the same libraries.
2. The one native customisation (immersive fullscreen) fits in a config plugin, ported from the source and
   trimmed of what the factory already handles (`local.properties`, splash cleanup if no longer needed on SDK 57).
3. Upgrades and Firebase stay cheap. The factory's tooling, templates and two published games are built and
   verified on Expo.

Rendering: one Skia `<Canvas>` drawing a picture rebuilt every frame from the pure engine state. The source draws
in `src/sprites/renderer.ts`, which is ported. Menus and overlays stay React Native Views. zustand is not needed:
the engine owns the game state (PRD deviation D1) and a small `route` state in `App.tsx` handles screens.
Reanimated is added only if the Skia loop needs `useFrameCallback`.

## Consequences

- `android/` is generated by `npx expo prebuild --clean` and git-ignored. Native changes go through config plugins
  (`plugins/with-fullscreen.js`, factory signing plugin, Firebase plugins).
- The source moves from SDK 55 to SDK 57. Skia, Reanimated and AsyncStorage versions come from `npx expo install`,
  not from the source `package.json`. Skia API changes between 2.4 and the SDK 57 version must be checked when
  porting `renderer.ts`.
- Skia adds several MB of native code: the 40 MB arm64 APK target must be checked at the first release build.
- The `VIBRATE` permission is declared in app config. `AD_ID` stays blocked.
- `expo-audio` playback needs no config plugin (`RECORD_AUDIO` is not requested).
- Bare: not chosen; `android/` would have been committed and maintained by hand.

## Alternatives considered

- **Bare React Native:** none of its triggers apply (no library lacking Expo support, no custom native module,
  no wish for manual native control), and it adds upgrade and Firebase setup work.
- **Views + Reanimated instead of Skia:** rejected for the game screen. There are too many moving elements, and
  the source drawing code is already Skia.
- **Staying on SDK 55 like the source:** rejected. The factory pins SDK 57, and its templates, plugins and
  verification are proven on it.
